## 全局变量

### 1.0 什么是全局变量

Solidity 提供了一些内置的 全局变量（Global Variables），用于访问区块链状态、交易信息等数据。这些变量不需要额外声明，可以在智能合约中直接调用

### 2.0 主要全局变量分类

solidity 全部变量分类：

#### 2.1 区块信息（Block Information）

|变量|类型|作用|
|---|---|---|
|block.number|uint|当前区块编号|
|block.timestamp|uint|当前区块时间戳（秒级）|
|block.coinbase|address payable|当前出块矿工的地址|
|block.difficulty|uint|当前区块难度|
|block.gaslimit|uint|当前区块的gas|
|block.basefee| uint|EIP-1559 之后的基本交易费|

示例：获取当前区块号和时间戳

```sol
contract BlockInfo {
    function getBlockDetails() public view returns (uint, uint) {
        return (block.number, block.timestamp);
    }
}
```
#### 2.2 交易信息（Transaction Information）

|变量|类型|作用|
|---|--|--|
|tx.gasprice|uint|交易的gas价格
|tx.origin|adress|交易的发起者（外部账户地址）|

注意：tx.origin 可能导致安全漏洞，避免用于身份验证！ 示例：检查交易发起者 contract TxInfo { function getTxOrigin() public view returns (address) { return tx.origin; } }

#### 2.3 消息信息（Message Information）
|变量|类型|作用|
|---|--|--|
|msg.sender|address|当前调用合约的地址（可能是外部账户或其他合约）|
|msg.value|uint|当前交易发送的以太币数量（单位：wei）|
|msg.data|bytes|当前调用合约的输入数据|

示例：获取调用者地址和发送的 ETH 数量



```sol
contract MessageInfo {
    function getMessageDetails() public payable returns (address, uint) {
        return (msg.sender, msg.value);
    }
}
```
#### 2.4 以太坊环境信息(Ethereum Environment Information)

|变量|类型|作用|
|--|--|--|
|gasleft|uint| 当前剩余的gas|
|block.chainid|uint|当前链的ID(EIP-1344)|
|address(this)|address|当前合约的地址|
|this.balance|uint|当前合约的ETH余额|

示例：获取当前合约的地址和余额

```sol
contract ContractInfo {
    function getContractDetails() public view returns (address, uint) {
        return (address(this), address(this).balance);
    }
}
```

#### 2.5 this 关键字
this 关键字用于引用当前合约的实例，它可以用于：

1. 获取当前合于的的地址
2. 在合约内部调用自身的函数（但会创建新的交易）
3. 访问当前合约的balance, 示例：使用this 关键子

```sol
    contract ThisExample {
        function getContractAddress() public view returns (address) {
            return address(this);
        }

        function getContractBalance() public view returns (uint) {
            return address(this).balance;
        }
    }
```

注意事项：
* this 关键字调用合约自身的函数时，会触发新的交易，因此会消耗额外的 gas。
* this.balance 获取的是合约的 ETH 余额，而 msg.sender.balance 可以用于获取调用者的余额。
